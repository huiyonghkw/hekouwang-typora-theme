# hekouwang 主题验收样张

> ——用来验收排版，也适合直接截进 README（浅色 / 深色各一张）

这一份把 Typora 常渲染的块基本铺满。中英混排是重点：西文走 Anthropic Sans / Inter，中文 fallback 到苹方——**这不是妥协，桌面端本身就是这个机制**。我自己验收时会把本文件开着，浅深各盯三分钟。

**阅读验收基线（Hekouwang）**：正文 `1rem` · 行高 `1.65` · 段距 `0.85rem` · 随宽屏从 `48rem` 扩至最多 `96rem` 的正文阅读列 / 最多 `120em` 技术画布 · `#write` 直角白纸。宽屏时检查长段落是否实际变宽，标题、列表与六列以内的表格是否同步对齐；1–3 列小表最多 `48rem` 并左对齐正文，4–6 列填满阅读列，7+ 列使用技术画布且只留横线。代码、宽表和图片也应有足够空间。本文件后半部包含专门的压力样例。

## 一、正文与中英混排

我写这段是为了看长段落的呼吸感。并排对照时，西文字形应接近 Anthropic Sans / Inter，中文走苹方；行距要像在读文章，不是在扫聊天气泡。

比如这句里混着 `variable font`、opsz 轴、以及 300→800 的字重范围，看看西文和苹方交接得顺不顺。数字也要对齐：2026 年、1,247 次、99.8% 的占比、测得 `font-size: 16px` 根字号。

行内样式一次过：**加粗看字重是不是真的**、*斜体/软强调*、~~删除线~~、`行内代码`、[一个链接](https://github.com/huiyonghkw/hekouwang-typora-theme)、以及 ==高亮==。

## 四、代码

行内的 `npm install`、`--user-data-dir`、`font-optical-sizing: auto`。

下面几块故意挨着放，用来验收**连续 fence 的呼吸**（不该糊成灰条墙）。

```python
import re

def check(css: str) -> list[str]:
    """判据必须能分辨合法与违规，一刀切等于没有区分力。"""
    problems = []
    for m in re.finditer(r"([^{}]+)\{([^{}]*)\}", css):
        selector = m.group(1).strip().split("\n")[-1].strip()
        if selector == "html":
            continue  # 合法：根字号可用 px
        for fm in re.finditer(r"font-size:\s*[\d.]+px", m.group(2)):
            problems.append(f"{selector} 里 {fm.group(0)}")
    return problems


if __name__ == "__main__":
    print(check(open("theme/hekouwang.css").read()) or "ok")
```

## 十二、宽屏长文

在 1440px 以上的窗口里，先连读下面三段，再缩到普通宽度读一遍。注意每行读到末尾后能否轻松找到下一行的开头，以及段落是否仍与标题、列表对齐。宽屏画布可以容纳复杂内容，但长段落应保持稳定的阅读节奏。

一份技术笔记往往先讲背景，再解释做法，最后列出边界。如果正文为了填满整个显示器而变得很宽，眼睛每次换行都要走更远，回到下一行开头时也更容易错位。阅读时请从这一段的第一句读到最后一句，不要只看页面是否居中；同时观察标点、英文缩写、年份和行内代码的间距，它们会在一行很长时放大排版中的小问题。

接下来把注意力放在内容的层次上。读者可能先扫标题，再跳到加粗的结论，随后回头看论证；也可能沿着段落逐句阅读，并在需要时打开旁边的大纲。段落宽度如果频繁变化，视线会不断重新建立起点。因此正文、引用和列表应形成一致的阅读列，而需要额外空间的表格、代码和图像可以按内容尺寸展开。

最后检查缩放后的体验：提高字号以后，卡片两侧仍应留有余地，长单词、路径和链接不应把整张页面撑出窗口。窗口缩小时，内容可以自然换行；确实不能拆开的技术内容应在自己的区域内滚动。连续读完这三段后，再切换深色主题重复一次，确认对比度与行距不会让文字显得过亮、过密或发灰。
